What this found

Ordered by severity. The live traffic badge marks defects only reachable by talking to real servers; offline suite marks the ones the unit tests caught while the rewrite was being written. Every one has a regression test.

F1 critical live traffic diagnosis.py

Cloudflare's injected JavaScript-Detections script was read as a challenge

Cloudflare injects a script from /cdn-cgi/challenge-platform/scripts/jsd/… into ordinary successful pages. That path was in the challenge marker list, so content pages were diagnosed as interstitials.

Why it mattered. 18 of 22 hosts reported as challenged were serving content normally. A caller would pay for a browser launch it did not need, or abandon a page it already had. The same marker also meant the browser solve loop never detected 'cleared' and burned the entire timeout on every solve — including the successful ones.

Fix. Require the challenge-only /h/ orchestrate sub-path. Measured across two live populations before changing: the bare prefix appeared on 9 of 10 normal pages, the /h/ path on 0.

Regression test. test_the_injected_detections_script_is_not_a_challenge, test_the_orchestrate_path_still_is_a_challenge

F10 critical offline suite transport.py

The impersonated transport never copied the response body

Response adaptation set status, headers and URL but not the content, so every impersonated response arrived empty.

Why it mattered. Nothing worked. Caught by running the two transports against a loopback server rather than a mock — the streaming path passed precisely because it did not read the body.

Fix. Copy the body, except on a streamed response where reading it would consume the iterator the caller is about to use.

Regression test. test_a_body_comes_back_as_a_requests_response (both transports)

F14 critical live traffic diagnosis.py

A proxy refusing our own credential was diagnosed as the site's IP reputation

A tor-pool that enforces authentication rejects the SOCKS5 handshake, which never becomes an HTTP response — so it arrived at diagnose_transport, which blamed the exit for every proxied transport error. The HTTP equivalent was already handled correctly: a 407 is reported as our credential, not a layer.

Why it mattered. Three wrong things followed from one wrong attribution. The address was rotated though nothing was wrong with it; the pool was told a healthy exit was blocked, damaging its health score; and — the durable one — layer 1 was written to the origin's persisted profile, so a missing environment variable left behind a permanent verdict that the site refuses this address. The visible symptom was four scenarios reporting that only a residential exit could help.

Fix. Distinguish 'the proxy refused us' from 'the path beyond it failed' on curl's own wording, and answer the first with REFUSE and no layer. Matched on the message rather than the exception class deliberately: an unreachable destination reported through a SOCKS5 reply raises the same ProxyError, and that one really is evidence about the exit.

Regression test. test_a_socks5_credential_rejection_is_not_layer_one, test_a_dead_destination_behind_a_good_proxy_still_blames_the_exit (+2)

F2 critical live traffic tiers/archive.py

A negative CDX limit silently returns an empty body

The Wayback index documents limit=-N as 'the last N rows', but combined with a filter it answers with nothing at all.

Why it mattered. The archive tier reported 'no usable capture' for every URL — indistinguishable from a URL the archive has never seen. The whole tier was dead, and the offline suite could not see it because it stubs the transport.

Fix. Bound the window server-side with from= and take the newest rows from the tail.

Regression test. test_the_index_is_never_asked_for_a_negative_row_count

F11 serious offline suite session.py

A throttle never widened the interval

The pacer was handed the decision's wait, which falls back to the interval already in force — so the widening was 'grow to what it already is'.

Why it mattered. The remedy for the hardest layer did nothing.

Fix. Feed the pacer the server's own Retry-After, not the fallback.

Regression test. test_a_throttle_widens_the_learned_interval

F15 serious live traffic exceptions.py, session.py

A failure with nothing to attribute was reported as layer 15

Blocked required a layer, so a stop with none — a proxy credential, an origin that never answered — was given Layer.WORKERS as a placeholder.

Why it mattered. 'L15 Operator edge code' is indistinguishable from a Cloudflare Worker refusing the request, so a mistyped proxy token produced a message pointing at the site. Surfaced while fixing F14: the attribution was gone and the message still lied.

Fix. Blocked.layer is Optional and renders as 'no detection layer'. An honest absence beats a plausible attribution — and pyright located both callers that had to learn about it.

Regression test. test_a_block_with_nothing_to_attribute_says_so

F3 serious live traffic tiers/archive.py

An unbounded index query times out on a popular URL

With no maximum age the query asked for a URL's entire history, which for a large site is slow enough to hit the timeout.

Why it mattered. Same symptom as F2 and the same misreading: a timeout looks exactly like 'never archived', so the tier appears permanently empty rather than slow.

Fix. The query is now always bounded — by the caller's maximum age when set, otherwise by a default window.

Regression test. test_the_query_is_always_bounded

F4 serious live traffic tiers/archive.py

An index that would not answer was reported as an empty archive

The index rate-limits. A single 503 came back as 'no usable capture'.

Why it mattered. The caller stops considering the archive for a URL it does hold.

Fix. Tell the two apart: a lookup failure now says so, an empty index says so, an age limit says so. Plus one retry, since a single 503 is routine.

Regression test. test_an_index_that_will_not_answer_is_reported_as_such, test_the_index_is_retried_once_before_giving_up

F5 serious live traffic links.py

Icon-font anchors were dropped as 'nothing rendered'

A home link written as <a><i class="fas fa-home"></i></a> has no text and no <img>, but renders a visible clickable icon. Icon fonts are how a large share of real navigation is marked up.

Why it mattered. Menus, pagination and home links silently skipped — the failure direction that actually costs content, as opposed to following a decoy.

Fix. Any element child counts as rendered. Only a genuinely empty anchor is a decoy signal.

Regression test. test_an_icon_font_link_is_clickable

F6 serious live traffic links.py

One URL took the verdict of whichever anchor came first

A content card is routinely an empty overlay anchor plus a text anchor to the same page, and the overlay comes first in the markup.

Why it mattered. On one real page, 11 of 11 rejections were wrong — the page yielded 77 followable links instead of 89. Combined with F5, whole navigation blocks vanished.

Fix. A URL reachable by any followable anchor is followable; the informative anchor wins.

Regression test. test_a_url_reachable_by_any_anchor_is_followable, test_a_url_only_reachable_by_a_decoy_anchor_stays_rejected

F7 serious live traffic planner.py

The stop advised configuring a capability that was already configured

A browser solver ran, produced no clearance cookie, and the resulting message said 'Configure a browser solver'.

Why it mattered. Sends the reader to check their configuration instead of the solver's output, which is where the actual reason is.

Fix. When the tier that owns the layer is present and still failed, the message says so and quotes what the tier reported.

Regression test. test_a_configured_tier_that_failed_is_not_advised_to_be_configured

F12 warning offline suite session.py

Success recorded the previously remembered tier, not the one that worked

A run that escalated to a browser wrote the old tier name back to memory.

Why it mattered. Every subsequent run started from scratch, defeating the point of persistence.

Fix. Record the tier that actually served the request.

Regression test. test_a_challenge_escalates_to_the_solver_and_then_succeeds

F13 warning offline suite exceptions.py

An impassable failure suppressed its own remedy

The route ('retrieve it with a properly obtained account') was a fallback, so any diagnosis that supplied its own detail hid it.

Why it mattered. The reader got a status code and no next step, for the one class of failure where there is exactly one next step.

Fix. Append the route rather than falling back to it.

Regression test. test_an_impassable_failure_always_carries_the_legitimate_route

F8 warning live traffic exits.py, planner.py

Rotating with nowhere to go spent the rotation budget on one address

A host banning this machine's whole ASN (Cloudflare 1005) produced a rotate decision, and with a single address configured each 'rotation' landed on the address that had just been refused.

Why it mattered. Wasted requests against a host that already said no, then a message that did not name the real problem.

Fix. The pool reports whether an alternative exists at all; with none, the stop is immediate and says to add a residential or mobile exit.

Regression test. test_rotating_with_nowhere_to_go_is_refused_immediately

F9 warning live traffic browser.py, pyproject

The browser extra failed with a raw dependency error on old Pythons

nodriver evaluates a PEP 604 union at import time, so it raises TypeError before Python 3.10 — not ImportError. On 3.14 one of its generated modules has a non-UTF-8 byte and raises SyntaxError.

Why it mattered. An unrelated error from inside a dependency, with nothing pointing at the version floor.

Fix. Catch the wider failure, name the version in the message, and mark the extra so it does not install where it cannot load.

Regression test. test_a_missing_solver_dependency_names_the_version_floor

Through a Tor exit

Of 45 Cloudflare hosts reached through the local tor-pool: 28 served outright, 10 challenged, 0 reputation-blocked.

A negative result worth keeping: the reputation layer is not uniformly hostile to Tor on this corpus. The model treats a Tor exit as clearing nothing at layer 1, which is conservative rather than measured — and the consequence is that a browser solver buys more here than a residential proxy would.

Reading the chart: the impersonated client meets the managed challenge on far fewer hosts, and meets the lighter scoring tiers less often — those are the layers a network signature answers. It meets the behavioural layer more often, which is not a regression: that is this session's own request volume against the same hosts being rate limited, and it is the one layer no client-side change addresses.
